BUTTON INPUT DURING ANIMATIONS — 26 November 2026

Changes
-------
Button feedback now scales only non-raycast decorative children through
FloodButtonFeedback3D. The Button's own rectangle, raycast graphic and interactable
state are not animated. Retriggering a button replaces only its own feedback;
hiding it restores its decorative children. This applies to both touch and mouse.
Screen/page/prompt transitions use CanvasGroup opacity instead of scale, without
changing interactable or blocksRaycasts. Existing modal blocking rules remain.

A remaining explicit lock was the committed Swap/Blast visual phase. During that
phase, palette and power-up selection buttons now remain available. Selecting a
new color or power-up finalizes the already-committed cell visuals immediately,
then processes the new selection. It does not repeat/refund the transaction or
spend a normal move. Cube painting stays protected until the old visual state is
finished. Loading, entrance, invalid actions and finalized results keep their
normal safety checks; new transactions cannot run simultaneously.
