MOBILE INPUT RESPONSIVENESS — 26 November 2026

Changes
-------
Mobile players request 60 FPS instead of inheriting the default frame target.
This is a request, not a guarantee that a GPU-bound device will render at 60 FPS.

Touch-capable UI keeps its screen, button, palette, page-grid and restart-card
hit areas at their final scale. These controls previously scaled while touches
could still be held. Buttons and screens also cancel old feedback tweens before
new feedback, preventing accumulated scale animations. Mouse-only UI retains
its scale feedback using unscaled time. Victory star/confetti animations remain.

Normal palette-only selections update immediately, then coalesce their checkpoint
write after 150ms of quiet. They no longer capture/serialize/write the entire board
inside every selection callback. A move, paid power-up transaction, navigation,
app suspension/focus loss or quit still uses the immediate save path. An abrupt
process kill during that short quiet window can lose only the latest unsaved
selection; completed moves are not deferred by this change.

Continue availability reuses validated data while the checkpoint path, timestamp
and size are unchanged. Save completion updates that cache; a changed/missing file
forces revalidation. Actual Continue still reads and validates before restoring.
Opening Levels while already in the menu avoids another full-board save. Returning
from gameplay continues to save normally.

The existing InputSystemUIInputModule, bindings and pointer behavior remain in use.
No second touch processor, pointer-down navigation or shared touch cooldown was
introduced. Audio rate limits remain separate from button action dispatch.
